# frameeyeosc

frameeyeoscは、Steam Frameの視線および目の開き具合（まぶたの位置）を読み取り、設定可能なプレフィックス付きで標準VRCFTパラメータを使用してOSC経由で送信します。GUIなしで動作します。目の開き具合は内部の共有メモリオブジェクト（`/dev/shm/eye-server.mmap`）を通じて公開されており、公開API経由ではありません。

トラッキングデータ書き込みプロセス（tracking data writer）は、この共有メモリにアイトラッキング値と更新タイムスタンプを書き込むプロセスです。この名称はその役割を表したものであり、書き込みを行う具体的なプロセスは特定されていません。生のアイトラッキングパラメータとは、frameeyeoscがキャリブレーションやフィルタリングを適用する前に共有メモリから読み取った値のことです。これらは必ずしも生のセンサー信号とは限らず、トラッキングデータ書き込みプロセス内部での処理内容は検証されていません。

## ビルドと実行

ヘッドセット上でRust/Cargoをインストールし、ビルドして実行します：

```sh
cargo build --release
runtime_dir=$(mktemp -d /tmp/frameeyeosc.XXXXXX)
./target/release/frameeyeosc --control-socket "$runtime_dir/control.sock" --target 127.0.0.1:9000
```

## OSC出力

### パラメータアドレス

各アドレスは `/avatar/parameters{prefix}` で始まります。デフォルトのプレフィックスは `/FT` で、設定されたプレフィックス末尾のスラッシュは削除されます。

| アドレスサフィックス | OSCの型 | 値 |
|---|---|---|
| `/frame/EyeTrackingActive` | boolean | トラッキング値の各セットの前に `true`、トラッキング停止通知では `false`。 |
| `/v2/EyeLeftX` | float32 | 左目の水平視線。[-1, 1] の範囲内。 |
| `/v2/EyeLeftY` | float32 | 左目の垂直視線。[-1, 1] の範囲内。 |
| `/v2/EyeRightX` | float32 | 右目の水平視線。[-1, 1] の範囲内。 |
| `/v2/EyeRightY` | float32 | 右目の垂直視線。[-1, 1] の範囲内。 |
| `/v2/EyeLidLeft` | float32 | 左まぶた出力。[0, `eyelid_output_cap`] の範囲内。 |
| `/v2/EyeLidRight` | float32 | 右まぶた出力。[0, `eyelid_output_cap`] の範囲内。 |
| `/v2/EyeX` | float32 | 注視点から導出された合成水平視線。[-1, 1] の範囲内。 |
| `/v2/EyeY` | float32 | 注視点から導出された合成垂直視線。[-1, 1] の範囲内。 |

例えば、デフォルトの左まぶたアドレスは `/avatar/parameters/FT/v2/EyeLidLeft`、トラッキング状態アドレスは `/avatar/parameters/FT/frame/EyeTrackingActive` です。

視線角度には `atan2(x, -z)` および `atan2(y, -z)` が使用され、45度が1、-45度が-1にマップされるようスケーリングされた後、[-1, 1] にクランプされます。VRCFTの規約では正のYは上向きを表しますが、この向きは実機ハードウェア上では未検証です。オプションのOne Euroフィルタリングは視線およびまぶた出力を平滑化します。まぶたには、生の正規化された開き具合か、キャリブレーション合成値のいずれかが使用され、その後に最終上限が適用されます。[まぶたの出力とフィルタリング](#まぶたの出力とフィルタリング) および [手動まぶたキャリブレーション](#手動まぶたキャリブレーション) を参照してください。

### トラッキング状態と配信

通常の更新では、`EyeTrackingActive` を true として送信し、続いて上記の8個のfloatパラメータを送信します。各パラメータは1つの引数を持つ個別のOSCメッセージであり、メッセージ群はアトミックなバンドルとしては送信されません。送信エラーが発生した場合、一部のメッセージが送信された後にセットが中断される可能性があります。

トラッキング停止通知では、`EyeTrackingActive` のみを false として送信し、視線やまぶたのゼロ値は送信しません。失敗した停止通知は、同じ送信先およびプレフィックスに対して再試行されます。OSC送信先がない場合、通知は送信できません。設定または送信先の変更時は、以前の送信先に追加の停止通知を送信することはなく、古い保留中の停止通知は破棄されます。[出力状態と停止通知](#出力状態と停止通知) を参照してください。UDP送信は、アバターまたはOSCレシーバーによる受信を確認するものではありません。

### トラッキングアドレスの移行

`/frame` 名前空間は、内部で `EyeTrackingActive` を使用するアバターアドオンとの衝突を回避します。以前の `/avatar/parameters{prefix}/EyeTrackingActive` アドレスを使用しているコンシューマーは、OSCマッピングを更新する必要があります。

## コマンドライン引数

保存値または明示的なCLI値が存在しない場合、以下のデフォルト値が適用されます。

### OSC送信先

| 引数 | デフォルト値 | 説明 |
|---|---|---|
| `--target HOST:PORT` | `127.0.0.1:9000` | 手動OSC送信先を設定します。 |
| `--target-mode manual\|auto` | `manual`（パネルモードでは `auto`） | 手動送信先を選択するか、ストリーミングピアのIPを推測します。 |
| `--target-host HOST` | `127.0.0.1` | 手動ホストを設定し、手動モードを選択します。 |
| `--target-port PORT` | `9000` | ストリーミングポートとは独立してOSCポート（1–65535）を設定します。 |
| `--prefix PATH` | `/FT` | アバターパラメータのプレフィックスを設定します。 |

### 共有メモリ入力

| 引数 | デフォルト値 | 説明 |
|---|---|---|
| `--shm-version auto\|4\|5` | `auto` | ABIを選択するか、ヘッダーから推測します。 |

### まぶたのキャリブレーションと出力

| 引数 | デフォルト値 | 説明 |
|---|---|---|
| `--eye-widening[=BOOL]` | `true` | キャリブレーションされた見開き（widening）の寄与を含めます。 |
| `--eye-widening-margin-left FLOAT` | `0.10` | 左目の脱力時最大値より上の、有限かつ非負の生マージンを設定します。 |
| `--eye-widening-margin-right FLOAT` | `0.10` | 右目の脱力時最大値より上の、有限かつ非負の生マージンを設定します。 |
| `--min-base-width FLOAT` | `0.10` | 閉眼から脱力時までの最小幅を設定します。有限かつ (0, 1] の範囲内。 |
| `--min-wide-width FLOAT` | `0.05` | 最小見開き区間幅を設定します。有限かつ (0, 1] の範囲内。 |
| `--eyelid-output-cap VALUE` | `1` | まぶたの最終出力をクランプします。有限かつ [0, 1] の範囲内。 |

プロファイルの作成方法およびこれらの設定がキャリブレーション済み出力にどのように影響するかについては、[手動まぶたキャリブレーション](#手動まぶたキャリブレーション) を参照してください。

### One Euroフィルタリング

| 引数 | デフォルト値 | 説明 |
|---|---|---|
| `--one-euro[=BOOL]` | `false` | 視線およびまぶた出力の平滑化を有効にします。 |
| `--one-euro-min-cutoff FLOAT` | `0.5` | 静止時の平滑化をHz単位で設定します。有限かつ正の値。小さいほど滑らかになります。 |
| `--one-euro-beta FLOAT` | `3.0` | 動きへの追従性を設定します。有限かつ非負の値。大きいほど高速になります。 |
| `--one-euro-d-cutoff FLOAT` | `1.0` | 速度（微分）の平滑化をHz単位で設定します。有限かつ正の値。 |

フィルタのデフォルト値はBaballoniaのOne Euro設定に準拠しています。チューニングオプションはフィルタリングが無効な間も受け付けられますが、有効化されたときにのみ効果を発揮します。

### 設定とパネル連携

| 引数 | デフォルト値 | 説明 |
|---|---|---|
| `--config PATH` | `$XDG_CONFIG_HOME/frameeyeosc/settings.json` | 保存設定ファイルを選択します。フォールバック先は `$HOME/.config/frameeyeosc/settings.json`。 |
| `--control-socket PATH` | `$XDG_RUNTIME_DIR/frameeyeosc/control.sock` | ユーザー所有の0700ディレクトリ内にあるIPCソケットを選択します。`XDG_RUNTIME_DIR` がない場合は明示的なパスが必要です。 |
| `--panel-mode` | オフ | 明示的または保存済みのターゲットモードが適用されない場合、デフォルトでautoターゲットモードにします。 |
| `-h`, `--help` | — | コマンドラインヘルプを表示します。 |

パスの検証、設定の永続化、およびランタイム更新については、[保存設定とIPC v1](#保存設定とipc-v1) を参照してください。

### 制約と優先順位

明示的な `--target` または `--target-host` の指定は、`--panel-mode` であっても手動モードを選択します。いずれかと明示的な `--target-mode auto` を組み合わせるとエラーになります。
`--target` を個別の host/port オプションと組み合わせることはできません。
スタンドアロン動作時のデフォルトは手動の `127.0.0.1:9000` です。`--panel-mode` は未指定時のターゲットモードのデフォルトを auto に変更します。保存された手動モードは手動のまま維持されます。
起動時、明示的なCLI値は保存値より優先され、保存値はデフォルト値より優先されます。ブール値オプションは `=` を伴う `true` または `false` を受け付けます。値を省略して指定するとそのオプションが有効になります。`--one-euro=false` は保存された true の値を明示的に上書きし、`--eye-widening=false` は見開きを無効化します。

### 使用例

```sh
./target/release/frameeyeosc --target-mode auto --target-port 9000
./target/release/frameeyeosc --shm-version 4 --eyelid-output-cap 0.7
./target/release/frameeyeosc --one-euro
```

## 保存設定とIPC v1

### プロトコル

IPC v1は、LF終端行ごとに1つのUTF-8 JSONオブジェクトを使用するUnixパス名ソケットを使用します。

| メソッドまたはイベント | 種別 | 目的 |
|---|---|---|
| `state.get` | リクエスト | 現在のスナップショットを読み取り、イベントを購読します。 |
| `settings.patch` | リクエスト | ランタイム時に設定を変更し、オプションでそれらを保存します。 |
| `state.changed` | イベント | 更新された状態スナップショットを受信します。 |
| `calibration.start` | リクエスト | まぶたキャリブレーションセッションを開始します。 |
| `calibration.begin_stage` | リクエスト | `closed`、`relaxed`、または `wide` ステージを開始します。 |
| `calibration.skip_wide` | リクエスト | wide を測定せずにキャリブレーションを完了します。 |
| `calibration.cancel` | リクエスト | セッションをキャンセルし、以前のプロファイルを保持します。 |
| `calibration.changed` | イベント | キャリブレーションの進行状況と結果を受信します。 |

スナップショットは、実際のアクティブなプロファイル、導出された目ごとの区間、現在のセッション、および最新の結果を公開します。

### 設定ファイルと起動時の優先順位

`--config PATH` は設定ファイルを選択します。そのデフォルトは `$XDG_CONFIG_HOME/frameeyeosc/settings.json` で、`$HOME/.config/frameeyeosc/settings.json` にフォールバックします。ファイルが存在しないことは許容されます。不正な形式のJSONや無効な既知の保存値は、たとえCLI値がそれらを上書きする場合であっても起動時エラーとなります。設定ファイルは64 KiBに制限されています。読み取りサイズは制限されており、サイズ超過ファイルは起動時エラーを引き起こします。同様の制限を超えるマージ結果の保存は、置換／適用の前に失敗します。未知の保存キーはディスク上に保持されますが、スナップショットには既知の保存設定のみが公開されます。CLIオプションは、省略された値と明示的なfalseを区別します。ランタイムパッチはCLI値を上書きできますが、次回の起動時には再び明示的なCLI値の優先順位が適用されます。

浮動小数点の設定（`eyelid_output_cap`、3つのOne Euro係数、両方の `eye_widening_margin_*` 値、`min_base_width`、`min_wide_width`）は、f64のJSON/CLI値を保持し、整数として記述された値を含め、現在および保存済みのスナップショットで同じ正規化された浮動小数点表現を使用します。`target_port` は整数のままです。未知の保存データや任意のリクエストパラメータが浮動小数点数に変換されることはありません。

### ソケット要件

`--control-socket PATH` はコントロールソケットを選択します。デフォルトは `$XDG_RUNTIME_DIR/frameeyeosc/control.sock` です。XDG_RUNTIME_DIR が存在しない場合は、スタンドアロン動作を含め、明示的なパスが必要です。

- 直前の親ディレクトリはこのユーザーが所有し、モード0700である必要があります。親ディレクトリが存在せずその祖先が既に存在する場合は、非公開で作成されます。既存のディレクトリは検証され、自動で chmod されることはありません。
- シンボリックリンクパスや他者所有のディレクトリは拒否されます。ソケットおよびロックファイルはモード0600を使用します。
- 古い（staleな）ソケットの探索および削除を行う前に、パスごとの非ブロッキングロックが取得されます。稼働中のソケットや通常ファイルが置換されることはありません。
- ロックのinodeを保持するため、シャットダウン後もロックファイルは残ります。

### 起動例

デフォルトのランタイム／設定パスの場合：

```sh
./target/release/frameeyeosc --panel-mode --one-euro=false
```

XDG_RUNTIME_DIR がない場合の明示的なパス：

```sh
runtime_dir=$(mktemp -d /tmp/frameeyeosc.XXXXXX)
./target/release/frameeyeosc --control-socket "$runtime_dir/control.sock" \
  --config "$HOME/.config/frameeyeosc/settings.json" --target-mode manual
```

### 接続と状態読み取り

接続後、最初に空でない文字列IDを指定して `state.get` を送信します。そのレスポンスには、`instance_id`、受信側の `connection_id`、現在／保存済みの設定、フィールドごとのソース（`cli`、`saved`、`default`、`panel`）、トラッキング、観測されたストリームピア、実際のOSCターゲット、および出力状態／理由が含まれます。ストリームの `connected` は、一意のピアが検出されたことを意味します。待機中または曖昧な観測結果は `unknown` にマップされます。ピアの不在は意図的な切断を確定できないため、この検出器が `disconnected` と判定することはありません。`sending` はUDP送信が試みられていることを意味し、受信確認ではありません。出力理由の優先順位については、[出力状態と停止通知](#出力状態と停止通知) を参照してください。

```json
{"v":1,"type":"request","id":"s1","method":"state.get","params":{}}
{"v":1,"type":"request","id":"p1","method":"settings.patch","params":{"patch":{"eyelid_output_cap":0.7,"one_euro":false},"save":true}}
```

### ランタイム時の設定変更

ブリッジの実行中にこれらの設定を変更するには `settings.patch` を使用します。現在のプロセスにのみ適用する場合は `save` を false に設定し、変更されたパッチキーを永続化（保存）もする場合は true に設定します。デフォルト値および対応するCLIオプションは [コマンドライン引数](#コマンドライン引数) に記載されています。

| キー | JSONの型 | 制約 |
|---|---|---|
| `eye_widening` | boolean | キャリブレーションされた見開きの寄与を有効または無効にします。 |
| `eye_widening_margin_left` | number | 有限かつ非負。 |
| `eye_widening_margin_right` | number | 有限かつ非負。 |
| `min_base_width` | number | 有限かつ (0, 1] の範囲内。 |
| `min_wide_width` | number | 有限かつ (0, 1] の範囲内。 |
| `eyelid_output_cap` | number | 有限かつ [0, 1] の範囲内。 |
| `prefix` | string | `/` で始まり、空白や制御文字を含まないこと。 |
| `one_euro` | boolean | フィルタリングを有効または無効にします。 |
| `one_euro_min_cutoff` | number | 有限かつ正の値（f32変換後も含む）。 |
| `one_euro_beta` | number | 有限かつ非負（f32変換後も有限）。 |
| `one_euro_d_cutoff` | number | 有限かつ正の値（f32変換後も含む）。 |
| `target_mode` | string | `manual` または `auto`。 |
| `target_host` | string | 有効なIP、スコープ付きIPv6、またはホスト名構文。DNSの可用性は個別にチェックされます。 |
| `target_port` | integer | 1から65535。 |
| `shm_version` | string | `auto`, `4`, または `5`。アクティブなキャリブレーションセッション中は拒否されます。 |

キャリブレーション区間の変更は、アクティブなプロファイルまたはすでに成功した relaxed 候補における有効なベース測定値も保持する必要があります。無効なパッチは全体として拒否されます。数値のJSON値は整数または小数として記述できますが、`target_port` は整数が必要です。

### ランタイム変更の保存

`patch` とブール値の `save` の両方が必須です。未知のパラメータ／パッチキーは失敗します。マージ候補は保存前に検証され、入力／UDPリソースが準備されます。変更されたパッチキーのみが保存され、他の保存キーは保持されます。同一ディレクトリ内の非公開0600一時ファイルに書き込まれてfsyncされ、現在の設定が適用される前に名前変更（rename）されます。名前変更がコミット境界となります。ファイルデータの同期は、電源喪失後のディレクトリエントリの残存を保証するものではありません。検証、準備、または保存に失敗した場合は、古い設定と保存値が保持されます。ABIの失敗時は、出力継続を報告する前に古いマッピングを再検証します。

### レスポンス、イベント、およびリクエストID

パッチレスポンスには、失敗時も含め、実際の `current`、`sources`、`osc_target`、`output`、および `save`（`saved`、`not_requested`、`failed`）が含まれます。すべてのレスポンスはオブジェクト `result`、ブール値 `ok`、および null またはオブジェクトの `error` を持ちます。イベントは最初の state レスポンスの後に開始され、受信側の接続IDを含む完全なスナップショットが含まれます。`caused_by` はパッチの送信元接続とリクエストIDを記録します。自発的なトラッキング／ストリームの変更では cause は null になります。すべてのリクエストとランタイムのティックは単一のシーケンシャルループ内で実行されます。パースされたメソッド／パラメータが同一である受け入れ済みIDが再度送信された場合、再適用や通知を行わずに元のレスポンスを返します（オブジェクトのキー順序は無関係です）。内容が変更されている場合は `id_conflict` を返します。無効なエンベロープやサポートされていないバージョンはキャッシュ検索の前に拒否され、受け入れやキャッシュ登録は行われません。

### 再接続と無効な入力

各接続は最大4096個のIDを受け入れ、エビクションなしですべての受け入れ済みレスポンスを保持します。ID数が上限に達すると新しいIDは `request_limit` を受け取りますが、既存のIDは引き続き再試行可能です。切断されるとキャッシュは破棄されるため、未確認の操作をリプレイするのではなく、`state.get` で再接続して実際の状態と同期（リコンシリアイル）してください。書き込み側をハーフクローズしたクライアントも、バッファリングされた完全なすべての行に対するレスポンスを引き続き受信します。不完全な末尾部分は破棄され、今後のイベント購読は停止し、有限の出力がフラッシュされた後に接続が閉じられます。不正な形式のJSON、非有限の数値、再帰的な重複キー、無効なUTF-8、または64 KiBを超える行を受信した場合、その行を部分適用することなくピアを切断します。

### リソース制限とスケジューリング

実装上のリソース制限は、同時接続クライアント数8、クライアントあたり1 MiBのキューイング出力、およびクライアントあたり16 MiBのキャッシュバイトペイロードです。正規化されたリクエスト、レスポンス行、およびIDはboxed bytes/stringsとして保持され、このバジェットはそれらの保持長さをカウントします。ハッシュテーブル／エントリ／アロケータのオーバーヘッドはさらに4096エントリに制限されているため、このバジェットは厳密なプロセスRSS制限ではありません。キャッシュ領域は変更前にレスポンス用の領域を確保して保守的にチェックされ、枯渇した場合は新しいリクエストを実行せずに切断します。出力制限を超えた低速クライアントは切断されます。毎回のポーリングでは最大4つの接続を受け入れ、クライアントあたり最大16 KiBを読み書きし、クライアントあたり1行（合計8リクエスト）を処理し、公平性のために先頭クライアントをローテーションします。一時的なacceptやクライアントごとのセットアップ失敗は最大1秒に1回ログに記録され、確立済みクライアントとOSCは動作を継続します。無効なリスナーエラーは致命的（fatal）です。これらの制限により、OSCティック間のIPC処理量が有限に保たれます。OSファイルシステム、procスキャン、およびDNS操作には依然として絶対的な実行デッドラインはありません。

### ローカルプロトコルテスト

`tests/fixtures/ipc-v1.jsonl` にある共有ワイヤ通信のサンプルは、シミュレートされたトラッキングデータの観測値とステージ時間を使用して、実際のソケットに対して検証されています。IDは比較のためだけに正規化され、測定の浮動小数点値はf32表現の違いを許容します。オブジェクトのキー順序や空白はワイヤ規約（wire contract）の一部ではありません。クライアントは生のレスポンスバイトを比較するのではなく、JSONをパースしてください。IPCテストは `tests/runtime_ipc/mod.rs` にバイナリテストモジュールとして含まれており、製品コードにCLIオプションを追加したりCargoの従来の統合テスト検出を無効にしたりすることなく、内部Runtimeパスが合成入力を使用できるようになっています。ヘッドセット／HMD実機の動作および実際のABI 5トラッキングデータ書き込みプロセスへのアクセスは未検証のままです。

## 手動まぶたキャリブレーション

### セッションのワークフロー

セッションを開始し、明示的に `closed`（閉眼）を開始し、次に `relaxed`（脱力・安静時）、その後 `wide`（見開き）を開始するかスキップします。各ステージは2秒間準備し、5秒間測定します。両目の中央値は独立しています。各ステージで記録される内容は以下のとおりです：

| ステージ | 準備 | 測定 | 目ごとの値 |
|---|---|---|---|
| `closed` | 2秒 | 5秒 | 生の開き具合の中央値。 |
| `relaxed` | 2秒 | 5秒 | 同じ有効サンプルからの中央値および最大値。 |
| `wide`（オプション） | 2秒 | 5秒 | 生の開き具合の中央値。 |

アクティブなセッションは1つのみ許可されます。失敗したステージは再試行のために自身の待機状態に戻り、それ以前のステージは保持されます。開始元接続の喪失を含むキャンセルの場合、古いプロファイルが保持されます。

```json
{"v":1,"type":"request","id":"start","method":"calibration.start","params":{}}
{"v":1,"type":"request","id":"closed","method":"calibration.begin_stage","params":{"session_id":"ID_FROM_START","stage":"closed"}}
{"v":1,"type":"request","id":"relaxed","method":"calibration.begin_stage","params":{"session_id":"ID_FROM_START","stage":"relaxed"}}
{"v":1,"type":"request","id":"skip","method":"calibration.skip_wide","params":{"session_id":"ID_FROM_START"}}
```

次のステージを開始する前に、対応するステージの結果を待ってください。イベントを購読するには、まず `state.get` を呼び出します。各操作のレスポンスは実際の `calibration` と `save` を返します。タイマーイベントと最新の結果は、契機となった `caused_by` IDを保持します。start/begin のレスポンスはリクエストの受理を示します。プロファイルの不可分（アトミック）な永続化と適用が完了して初めて、完了が成功したことになります。

### 測定要件

測定には、5秒間の全ウィンドウにわたって観測された更新ケイデンスに対して、少なくとも80%の一意な有効サンプルが必要です。タイムスタンプ間隔の中央値には、少なくとも10個の正の差分が必要です。ケイデンスが不明であるか、80%の境界でのタイムスタンプ分解能が不十分な場合、ステージは再試行のため失敗となります。重複したシーケンスやタイムスタンプによってカバレッジが増加することはありません。測定中のトラッキングデータ書き込みプロセスの再起動、タイムスタンプの逆行、または入力の置換が発生した場合も、そのステージは失敗します。非アクティブまたは無効なサンプルはカバレッジ不足となります。[0, 1] の有限な生の開き具合のみが測定され、0および1は有効な値のままです。追加の外れ値除去は適用されません。ケイデンスは観測されたタイムスタンプから推測されるため、配信が一貫してスキップされると推定値にバイアスが生じる可能性があります。これは分布やヘッドセットの装着感を保証するものではありません。

### キャリブレーション済み出力

キャリブレーションされた closed は0にマップされ、relaxed は内部の Openness=1 にマップされます。見開き（widening）は `relaxed_max + margin` から始まります。使用可能な測定済み見開き区間は EyeWide=1 にマップされます。独立した各コンポーネントは、`0.75 * Openness + 0.25 * EyeWide` を合成して最終的な上限（cap）を適用する前に、オプションでフィルタリングされます。見開き区間が存在しないか不十分な場合は寄与度がゼロとなりますが、ベース区間と測定された見開き値は保持されます。生の wide=1 単体でも許可されます。見開きが無効化されている場合でも、ベースの寄与度は引き続き relaxed を 0.75 にマップします。見開きフィルタは無効化されている間も更新を継続します。再キャリブレーションまたは区間設定の変更を行うと、まぶたの履歴はリセットされます。

### チューニングとランタイム変更

```sh
./target/release/frameeyeosc --eye-widening=false --eyelid-output-cap 0.7
./target/release/frameeyeosc --eye-widening-margin-left 0.10 \
  --eye-widening-margin-right 0.10 --min-base-width 0.10 --min-wide-width 0.05
```

`eye_widening` のデフォルトは true です。目ごとのマージンのデフォルトは 0.10 であり、有限かつ非負でなければなりません。最小ベース幅および最小見開き幅のデフォルトはそれぞれ 0.10 と 0.05 であり、(0, 1] の有限値でなければなりません。これら5つの値はすべてCLI、保存設定、およびランタイムパッチのキーです。マージンや最小見開き幅を変更することで、測定値を失うことなく見開き区間を無効化でき、それらを下げることで再度有効化できます。アクティブなプロファイルまたはすでに成功した relaxed 候補を無効化するパッチは、全体として拒否されます。アクティブなセッションは、`shm_version` を含むすべてのパッチを拒否します。

### プロファイルの保存と復旧

プロファイルは、設定パスに `.profile.json` を付加した別ファイルとして保存されます（例: `settings.json.profile.json`）。デフォルトは `$XDG_CONFIG_HOME/frameeyeosc/settings.json.profile.json`、または `$HOME/.config/frameeyeosc/settings.json.profile.json` です。プロファイルには、目ごとの4つの測定値（`closed`、`relaxed`、`relaxed_max`、およびオプションの `wide`）のみが含まれます。完了時には、CLI／ランタイム設定をついでに保存することなく、このプロファイルが保存されます。プロファイルが存在しない場合は生出力が使用されます。無効な構造またはベース測定値の場合は診断メッセージを出力して生出力を使用しますが、その後のキャリブレーション成功による上書きは許可されます。不正な `wide` 値単体の場合、その目の見開きのみが無効化されて `invalid_wide` が報告され、両目の有効なベース区間ともう一方の目の有効な見開き測定値は保持されます。保存に失敗した場合は以前のプロファイルが保持され、`save_failed` が報告されます。

### IPCサイズ制限

バックエンドの受信リクエストの制限は、LF終端行あたり64 KiBです。完全な送信スナップショットは、バックエンドの1 MiB出力キュー制限の範囲内で現在値や保存値が長い文字列を繰り返す可能性があるため、そのサイズを超えることがあります。そのため、パネルは受信レスポンス／イベント行を1 MiB、送信リクエストを64 KiBに制限しています。

## 送信先検出と復旧

### 自動送信先の選択

Autoモードは、`vrlink` という名前の実行可能ファイル、それが所有するソケットinode、およびそのプロセスのネットワーク名前空間内の `/proc/<pid>/net/udp{,6}` を検査します。所有されており接続されているUDPピアのみが候補となります。匿名化されたアダプターフィクスチャのピアは `192.0.2.20:10400` です。10400はストリーミングトランスポートポートであるため、autoモードは検出されたIPのみを使用し、別途設定されたOSCポート（デフォルト9000）と組み合わせます。

### ピアの適格性

ループバック、未指定、およびマルチキャストアドレスは除外されます。グローバルIPv6はサポートされます。インターフェーススコープのないリンクローカルIPv6は、使用可能なピアを待機します。複数の異なるピアIPが存在する場合は曖昧となり、OSCのターゲットが存在しない状態（ターゲットなし）になります。候補プロセス／ソケットの消失や、不完全なproc観測時も待機状態となります。無関係なファイル記述子の変動（descriptor churn）によって、検証済みピアが無効化されることはありません。IPv6が無効化されたカーネルなど、UDPファミリテーブルが存在しない場合も許容されます。実行中の `vrlink (deleted)` 実行可能ファイルは、Steamバイナリのアップデート後も対象として適格なまま維持されます。次の完全な観測によって、ストリーム再起動後に復旧可能です。手動モードは、ストリームの観測結果に関係なく設定された送信先を維持します。

### 手動送信先の再試行と検出の制限

初回の手動DNS／ソケットセットアップが一時的に利用できない場合、ブリッジは `no_target` に留まり、解決されるまで1秒に1回再試行します。不正なホスト／IP構文はセットアップ前に拒否されます。システムのDNS解決はブロックされる可能性があります。入力待機バジェットはOSリゾルバのデッドラインを保証しません。検出はプライベートストリーミングプロセスからの推測であり、相手のピアがOSCレシーバーであることの証明ではありません。

## 共有メモリ入力と復旧

### ABIの選択

`--shm-version` のデフォルトは auto です。ヘッダーバージョンと必要なファイルサイズによってパックされたレイアウトが選択されます。ABI 4 はレコードオフセット `0x152` とサイズ `0x4f21a` を使用し、ABI 5 は `0x157` と `0x4f21f` を使用します。

### 利用不可な入力と再試行

明示的なABIの不一致、入力の欠落または未初期化、およびファイルの置換／リサイズが発生した場合、ブリッジは常駐したままトラッキング出力を停止します。サイズが小さすぎるファイル、バージョンゼロ、または未初期化の共有メモリファイルは、ABI不一致ではなく「利用不可（unavailable）」として扱われます。再オープンおよびターゲット検出は1秒間隔で再試行されます。

### 更新タイミングとサンプルの有効性

共有シーケンスのfutex待機とミューテックス取得は1回の呼び出しあたり10 msのバジェットを共有し、固定の1 kHzポーリングループを回避しています。このスケジューリングバジェットにより、一時的な更新なしポーリング時でもトラッキング／フィルタ履歴が保持されます。トラッキングデータの更新なしで丸1秒が経過すると、非アクティブ（inactivity）が確定します。非アクティブ、または無効／非有限のアイサンプルが発生した場合、両目を停止し、フィルタ履歴をリセットします。開き具合0は引き続き有効です。[0, 1] を超える有限の生の開き具合の逸脱に対しては、既存のクランプ動作が維持されます。

### トラッキングデータの中断と復旧

ミューテックス所有者が死亡した後、ミューテックスは整合性のある状態に修復され、不完全である可能性のあるレコードシーケンスは破棄されます。その後のトラッキングデータ更新のみが送信可能となります。読み取りの前後でヘッダー、サイズ、およびパス名の同一性がチェックされます。チェック間における外部による並行mmap切り捨て（truncation）は、プラットフォームレベルのハザードとして残ります。ABI 5 および自動送信先は、ヘッドセット実機ハードウェアでは未検証です。

## まぶたの出力とフィルタリング

### 出力上限と平滑化

`--eyelid-output-cap` は、オプションのフィルタリングおよびキャリブレーション合成後に両まぶたをクランプ（上限制限）します。有効なプロファイルがない場合、生の互換パスが既存の正規化とフィルタリングを維持します。上限（cap）が1の場合、未キャリブレーションの生の値は変更されません。

One Euroフィルタリングはオプトイン（明示的有効化）であり、正規化後の視線およびまぶたの出力を平滑化します。フィルタの計算およびOSC値にはf32精度が使用され、係数は有限な正／非負のf32変換が可能かチェックされます。

### 出力状態と停止通知

最初に一致した条件によって出力理由が決定されます：

| 優先度 | 理由 | 条件 |
|---|---|---|
| 1 | `input_unavailable` | 共有メモリ入力が利用できない。 |
| 2 | `abi_mismatch` | 入力のABIに互換性がない。 |
| 3 | `no_target` | 利用可能なOSC送信先がない。 |
| 4 | `invalid_sample` | 入力に無効なアイサンプルが含まれている。 |
| 5 | `tracking_inactive` / `tracking_unknown` | トラッキングがfalse / トラッキング状態が不明。 |
| 6 | `sending` | トラッキングがアクティブで、OSC送信先が利用可能。 |

これらの理由はランタイム状態を表すものであり、UDP配信が確認されたことを意味するものではありません。送信先がない場合、ブリッジはOSCトラッキング停止通知を送信できません。設定または送信先を切り替える際、以前の送信先に余分な停止通知が送信されることはありません。通常のトラッキング停止通知の送信に失敗した場合、送信されるかトラッキングが再開されるまで、同じ送信先／プレフィックスに対して再試行されます。設定の切り替えにより、保留中の古い通知は破棄されます。繰り返されるOSCエラーログは、エラーの種類ごとに1秒に1回に制限されます。

## 生のアイトラッキングパラメータ測定と候補の評価

### キャプチャ条件

ヘッドセット上で標準ライブラリのみで動作するPythonツールをローカルで実行します。各条件を個別にキャプチャしてください。デフォルトの準備時間は2秒、測定時間は5秒です。標準出力に出力されるJSONLには、スキーマ1のメタデータ、サンプル、およびサマリーが含まれ、すべてのレコードに指定されたセッション、条件、およびラベルが付与されます。

```sh
python3 scripts/eye_measure.py capture --condition closed --session fit-1 --label closed-1 > closed.jsonl
python3 scripts/eye_measure.py capture --condition relaxed --session fit-1 --label relaxed-1 > relaxed.jsonl
python3 scripts/eye_measure.py capture --condition wide --session fit-1 --label wide-1 > wide.jsonl
python3 scripts/eye_measure.py capture --condition relaxed --session fit-1 --label natural-repeat-1 --duration 60 > natural-1.jsonl
```

通常のまばたきを含む独立した自然開眼（natural-open）の検証データを収集する間は、キャリブレーションのキャプチャデータを固定したままにします。試行を繰り返すごとに新しいラベルを使用し、ヘッドセットを外して再度装着した後は新しいセッションを使用してください。オプションの `left-wink` および `right-wink` 条件は、左右非対称性の確認に役立ちます。

### 入力選択とリプレイ

`--shm-version` は `auto`（デフォルト）、`4`、または `5` を受け付けます。互換性のないヘッダーやサイズは拒否されます。
`--source FILE.jsonl` は、ハードウェアにアクセスすることなく既存の生サンプルをリプレイします。リプレイでは測定時間を証明できないため、品質は unknown（不明）として報告され、中断または失敗したソースの場合は failed として報告されます。`replay_source` は元の条件、セッション、ラベル、品質、および中断情報を保持します。非有限サンプルのサニタイズによる null 値は無効としてカウントされ、リプレイは継続されます。リプレイでは元の測定時間が未検証であるため、所要時間、経過時間、期待サンプル数、有効カバレッジ、および欠落サンプル数の推定値は null のままになります。中断されたリプレイは中断理由を保持し、失敗したソース品質には `source_quality_failed` を使用します。JSONLはすべての非空行にオブジェクトが必要です。入力エラーが発生した場合は該当ファイルと行を特定し、失敗したキャプチャサマリーを生成します。

### 明示的候補の評価

明示的な候補パラメータをオフラインで比較します。4つの数値がすべて必要です。以下の値は候補パラメータの例であり、製品のデフォルト値や自動選択された値ではありません。検証引数を複数回指定することで、同じキャリブレーションに対して自然開眼の繰り返しデータや再装着後のセッションを評価できます。

```sh
python3 scripts/eye_measure.py evaluate \
  --closed closed.jsonl --relaxed relaxed.jsonl --wide wide.jsonl \
  --validation-relaxed natural-1.jsonl --validation-relaxed natural-refit.jsonl \
  --margin-left 0.05 --margin-right 0.02 \
  --min-base-width 0.05 --min-wide-width 0.05
```

### 評価結果とソース品質

サマリーには、各目のキャリブレーション中央値、脱力時最大値、`wide_start = relaxed_max + margin`、使用可能区間、および検証時の `EyeWide > 0` の割合が報告されます。分布サマリーは EyeWide および `min(1, 0.75 * base + 0.25 * EyeWide)` を対象とします。サマリーのみの過去のフィクスチャはキャリブレーションの代表値を提供できますが、検証用の生サンプルを持たないため、リーク率は null、ステータスは unknown となります。ソースオブジェクトは、パス、条件、セッション、ラベル、品質、中断、およびサマリーの有無を保持します。既知の条件の不一致は拒否されます。レガシー入力の場合、条件名と完全に一致するラベルがこのチェック用の条件として提供されます。任意のラベルは推測されず、`condition_verified: false` となります。quality フィールドを持たないレガシー入力も引き続き使用可能であり、`quality: unknown` および `legacy_quality_missing` となります。未完了の入力には `summary_missing` が付与されます。これらの入力、ならびに失敗または中断されたキャプチャでは、`source_quality_ok` は false となります。そのような入力からの数値的な生観測データは、品質承認ではなく検証ステータス `unqualified`（不適格）となります。

### 独立検証と集計結果

ファイルごとの検証レポートにより、各ラベルや再装着セッションを個別に比較できます。ソースはデバイス／inodeのファイル同一性を記録します。キャリブレーションのinodeと一致する検証ファイル（シンボリックリンクやハードリンクを含む）、または同じ非nullのセッション／ラベルおよび同じ条件を共有する検証ファイルは、`validation_overlaps_calibration: true` を持ちます。それらの生観測データは表示されたまま残りますが、独立した検証としては不適格と見なされます。生データとサマリーのみが混在する検証セットは `aggregate_partial: true` となります。表示される分布は生データのサブセットを対象とし、全体の利用可能性は false、全体のリーク率は unknown となります。ファイルごとの観測データは引き続き個別に利用可能です。重複する検証ファイルや一致する測定同一性は、集計に1回のみ含まれます。`duplicate_validation_input`、`included_in_aggregate`、`duplicate_of` が除外されたコピーを特定します。それらが存在する場合、観測されたリーク率とファイルごとの結果は保持されますが、全体の集計は不適格となります。unknown の理由は、生データの欠落と使用不可能な base/wide 区間を区別します。wide のみが使用不可能な場合、EyeWide は無効化（0）され、base の分布は引き続き 0.75 を寄与し、リーク率は unknown のままになります。キャリブレーションは保存されません。

### キャプチャ品質とカバレッジ

キャプチャは、トラッキングがアクティブであり、両目に [0, 1] の有限値が含まれている場合にのみスナップショットを受け入れます。トラッキングデータ書き込みプロセスからの一意の有限なタイムスタンプから、単調増加エポック内の少なくとも10個の正の差分に基づいて観測ケイデンスが確立されます。推定期待サンプル数は要求された完全な測定期間を使用するため、早期に停止した観測90 Hzストリームはカバレッジを失います。品質要件としては、少なくとも5秒間の測定完了と80%の有効カバレッジが必要です。短いデバッグキャプチャや中断された実行が合格することはありません。

### タイムスタンプ分解能

カバレッジの不確実性は、浮動小数点のタイムスタンプ間隔（`math.ulp`）と、中央値周期の1.5倍未満のステップ間の観測間隔を組み合わせて算出されます。より長いスキップ更新の倍数や停止／再開のギャップは粒度（grain）推定から除外されますが、カバレッジの算出には依然として完全な測定時間が使用されます。終点浮動小数点間隔の2倍以内のステップ変動は表現ノイズとして扱われます。これにより観測された粒度が推定されますが、均一なタイムスタンプや未観測のステップサイズから基礎となるハードウェアクロックの粒度を確立することはできません。品質判定は依然として観測されたケイデンスを前提とします。得られた不確実性バンドの外側にあるカバレッジは、直接合格または不合格と判定されます。80%前後のバンド内では、丸め補正は1サンプルのカバレッジの半分未満の場合にのみ許可されます。それ以上の曖昧さがある場合は、`timestamp_resolution_insufficient` を伴う `unknown` を返します。境界から離れた長時間のキャプチャは判定可能なままです。サマリーには観測された粒度とカバレッジの不確実性が公開されます。`timestamp_resolution_ok` は、明らかに高／低カバレッジを分類できるかどうかではなく、単一サンプル境界の精度を表します（周期が不明な場合は null です）。リプレイ時のクロック診断はすべて null です。テストされたクロック原点 0、4e6、および 1.8e9 において、360/450 は合格し、359/450 は不合格となります。どのような分解能であっても中断時は不合格となります。

### ケイデンス制限と欠落サンプル

ケイデンスの欠落またはトラッキングデータ書き込みプロセスの再起動は品質 unknown を生じさせます。これは観測されたケイデンスの推定値です。スキップ更新の繰り返し、真に混在した更新周期、一貫して低速なトラッキングデータ書き込みプロセスはその中央値にバイアスをかける可能性があります。合格した結果は、ハードウェアの公称レートを証明するものではありません。信頼性を評価する際は、カウンター、生サンプル、および繰り返し試行を確認してください。欠落サンプルの推定値は `expected_samples - valid_snapshots` を使用し、非アクティブ／無効な更新を欠落した有効カバレッジに含め、この根拠を明示的に指定します。準備時間はベースラインを確立するためのものであり、測定サンプル分布からは除外されます。

### キャンセルとトラッキングデータの中断

キャプチャエラー時は error フィールドを含む失敗サマリーが出力されます。ミューテックス待機中の停止は、ビジー（busy）ではなくキャンセル（cancellation）として分類されます。Ctrl-C は中断サマリーを出力して終了ステータス130で終了します。制限付きミューテックス待機時間は最大0.5秒であり、終了時にリソースが解放されます。ミューテックス所有者が死亡した場合、キャプチャはRust側のリーダーと同様にミューテックスを整合させ、新しい更新を要求し、不完全である可能性のあるレコードとそのシーケンスを破棄します。測定中の破棄は `owner_dead_discarded` としてカウントされ、更新や有効サンプルとしてカウントされることは決してありません。

### ABIの証拠とハードウェアの制限

ローカルのABIおよびライフサイクルテストは、ヘッドセット実機での検証に代わるものではありません。キャプチャリーダーはスナップショットの前後でヘッダーとファイルサイズをチェックします。チェック間における外部による並行mmap切り捨ては、プラットフォームレベルのハザードとして残ります。

ABI 4/5 の共有制御ヘッダーは、固定リファレンス [sasaken1102r/frameeyeosc at af2610e](https://github.com/sasaken1102r/frameeyeosc/blob/af2610e4c396ca9d6fc47fe0054b9ae7c1d6d85d/src/main.rs#L125-L166) によって裏付けられています。両方のレイアウトで制御ヘッダーが0に配置され、ミューテックスが0x08、シーケンスが0x38、リクエストが0x3cに配置されることが、その [オフセットアサーション](https://github.com/sasaken1102r/frameeyeosc/blob/af2610e4c396ca9d6fc47fe0054b9ae7c1d6d85d/src/main.rs#L214-L223) によって確認されています。これはソースコードレベルのABIの証拠であり、ローカルの合成テストや上記リファレンスは、実際のABI 5トラッキングデータ書き込みプロセスへのアクセスの成功を立証するものではありません。
