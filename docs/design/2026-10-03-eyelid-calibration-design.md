# 左右別まぶたキャリブレーションと見開き合成

判断日: 2026-10-03。採用・更新日: 2026-10-10。状態: **accepted**。以下は今回のキャリブレーション・見開き合成の実装仕様であり、製品機能の実機合格を意味しない。
この文書は同日時点の `frameeyeosc` のまぶた出力追加の実装仕様。リポジトリ全体へ恒久的な規約を追加するものではない。

## 対象と根拠

対象は左右別の入力キャリブレーション、見開き合成、その有効・無効設定、最終出力の clip、保存・再利用。
左眼が開きやすく見える差を、左右別の補正と最終 clip により補正し、ウィンクを保持する。左右の平均などによる追加均一化は含めない。
内部 Openness と EyeWide から最終 EyeLid を合成し、見開き合成だけを CLI・設定で有効・無効にする。
各段階は手動開始・準備2秒・計測5秒・中央値を採用し、自然開眼の有効サンプル最大値に左右別の追加余裕を加えて見開き開始値を決める。有効サンプル率80%以上を必要とする。追加余裕各0.10、最小開閉幅0.10、最小見開き幅0.05を変更可能な初期値とする。これらは[実測比較](../research/2026-10-10-eyelid-measurement.md)を参考に選んだ値であり、全利用者への最適性や誤検出ゼロを保証しない。不正profileは診断して未校正で起動し、再測定できる。設定キーはIPC設計に定義する。

前段階の実装は raw openness を 0..1 に clamp し、`OptionalEyeFilter` を通して最終 `v2/EyeLidLeft/Right` に送り、設定保存と状態IPCを備える。今回そこへキャリブレーション・見開き合成を追加する。
ABI v4基準・v5選択とauto判定はこの文書の対象外であり、選択キー `shm_version`（auto/4/5）と入力再open・version/size検証は[IPC設計](2026-10-06-panel-ipc-design.md)に従う。この文書は ABI、接続先検出、IPC 全体、新しい OSC 出力モード、C++ パネルを実装する仕様ではない。

## 内部値と最終出力

左右それぞれに `Openness` と `EyeWide` を持つ。内部 `Openness` は閉眼 0・自然開眼 1、`EyeWide` は自然開眼 0・十分な見開き 1。
最終アバター値は次式とし、内部 Openness の自然開眼値と混同しない。

```text
lid = 0.75 * Openness + 0.25 * (eye_widening ? EyeWide : 0)
output = clamp(lid, 0, eyelid_output_cap)
```

| 状態 | Openness | EyeWide | 合成値（clip 前） |
| --- | --- | --- | --- |
| 閉眼 | 0 | 0 | 0 |
| 半開きの例 | 0.5 | 0 | 0.375 |
| 自然開眼 | 1 | 0 | 0.75 |
| 十分な見開き・合成有効 | 1 | 1 | 1 |
| 十分な見開き・合成無効 | 1 | 1 | 0.75 |

`eyelid_output_cap` は有限な 0..1、既定 1 とする。全区間へ倍率を掛けず、合成後の上限だけを clip する。
見開き合成無効かつ cap >= 0.75 なら自然開眼 0.75 と途中の開閉値を保持する。cap < 0.75 なら自然開眼と cap を超える半開きも意図的に clip される。
左右を共通値に置き換えず、左閉眼・右自然開眼とその逆を独立して保持する。

## キャリブレーションと区間変換

各眼に raw の `closed`、`relaxed`、任意の `wide` を保存する。左右の自然開眼 raw 値が違っても、それぞれを内部 Openness=1 に対応させる。
手動測定は閉眼、力を抜いた自然開眼、任意の見開きの順に行い、各段階をユーザーが明示的に開始する。各段階は準備2秒・計測5秒とし、その段階の追跡有効な有限サンプル中央値を代表値にする。自然開眼の5秒間では同じ有効サンプル集合の最大値 `relaxed_max` も左右別に測定し、見開き開始の基準に使う。準備中・他の測定段階・追跡無効・非有限のサンプルはこの最大値に含めない。新しい外れ値除去アルゴリズムは追加しない。
各段階の成立には5秒の計測と有効サンプル率80%以上の両方を必要とする。率は5秒間の期待producer更新数に対する有効な一意producerサンプル数とし、poll回数や同一timestampの繰り返しを数えない。期待更新数はproducer更新頻度に基づいて算定する。観測cadenceの推定と低頻度・欠測時の扱いは[README](../../README.md#manual-eyelid-calibration)に記録する。今回の実測約90Hzなら約450更新中約360有効に相当するが、固定360個を必須条件にしない。80%は欠測を排除する運用基準であり、自然開眼分布の保証ではない。
無効サンプルや短いglobal inactiveは欠測として扱い、その1回だけで段階を即失敗にしない。5秒終了時に有効率を判定する。追跡停止の検出は診断とし、採取が不足した段階は有効率不足として再測定する。
測定中は既存の有効profileを使い続ける。失敗した段階は同段階の待機へ戻して手動で測定し直し、成功済み段階の候補を保持する。途中cancelでは候補を破棄して旧profileを保持する。[IPC設計](2026-10-06-panel-ipc-design.md)では、閉眼・自然開眼の成功後は見開きの選択待ちとし、見開き完了または省略で候補をatomic保存してから適用する。保存失敗は旧profileを保持した終端失敗とする。
見開き段階は省略可能。各眼の `wide` が無効でも、その眼の有効な閉眼〜自然開眼キャリブレーションは維持する。
保存profileの読込でも、基礎区間が有効でwideだけが不正なら、その眼のwideをnull・利用不可理由をinvalid_wideとして基礎区間を保持し、反対眼の有効なwideも保持する。JSONやprofile構造全体の破損、基礎測定値の不正、現在設定での基礎区間不足は後述の未校正raw起動へ戻す。

自然開眼より上の見開き開始までのデッドゾーンを左右別に設定可能にする。初期値は自然開眼の最大値側に寄せ、正の追加余裕 `margin` を多めに取る保守的方針とし、左右とも既定0.10とする。raw 単位の幅 `d` と開始値の関係は次式。閉眼〜自然開眼の線形区間は変更しない。

```text
d = (relaxed_max - relaxed) + margin
wide_start = relaxed + d = relaxed_max + margin
Openness = clamp((raw - closed) / (relaxed - closed), 0, 1)
EyeWide = valid_wide ? clamp((raw - wide_start) / (wide - wide_start), 0, 1) : 0
```

閉眼以下は 0、自然開眼から wide_start までは Openness=1 / EyeWide=0 に落ち着き、閉眼〜自然開眼と見開き区間は線形・連続・単調に変換する。自然開眼より大きい raw でも Openness は 1 を超えない。
追加余裕は左右とも既定0.10、最小基礎区間幅は既定0.10、最小見開き区間幅は既定0.05とする。3種類とも固定の検証定数ではなく数値設定として保存・CLI・IPCから変更できる。標本の成立基準は前述の計測5秒・有効サンプル率80%以上とする。
2026-10-04 JST の自然開眼 raw 測定では p95 − median が左 0.032011、右 0.028648 だった。これは既存の揺れの観測であり、最大値に加える余裕の具体値や合格閾値を確定するものではない。最終出力・フィルタを含めた見開きの漏れは未検証。
`closed < relaxed`、`relaxed - closed` が最小幅以上、各値が有限であることを検証する。
見開きには `wide - wide_start` が最小幅以上の別検証を行う。デッドゾーンによって潰れた区間も含め、未測定・不正・飽和で不足した眼の EyeWide は 0 とし、反対眼の区間を借用しない。品質条件を満たした測定wide値は区間不足でも保存・保持し、現在marginからd/wide_startと見開き利用可否を変更ごとに再計算する。見開き区間を成立させるために開始値や追加余裕を黙って縮めず、誤検出を抑える選定を維持する。
自然開眼 raw と見開き raw がともに上限へ飽和している場合、区間補正や ABI v5 の選択だけで失われた見開き情報を復元できるとは扱わない。飽和は別の数値閾値で拒否せず、上記の区間不足として判定する。wide=1.0だけを理由に無効化せず、有効な幅が残る眼では見開きを利用できる。
再装着を含む実測でも自然開眼に有効なraw=1.0が混在した（[測定報告](../research/2026-10-10-eyelid-measurement.md)）。対応は既存の見開き無効設定とし、新しい外れ値除去・誤検出抑制処理は追加しない。有効サンプル最大値、区間不足の眼のEyeWide=0、基礎区間の保持を維持する。
有効なprofileがない未キャリブレーション時は既存raw互換経路を維持し、既存フィルタ後に `output=clamp(raw_path_value,0,eyelid_output_cap)` の最終capだけを適用する。rawへ0.75を掛ける校正後の合成式は使わない。見開き合成を有効にするだけで未測定の見開きを生成しない。

## 設定と保存

| 設定 | CLI | 既定値・範囲 |
| --- | --- | --- |
| `eye_widening` | `--eye-widening=<true\|false>` | true。見開き項だけの有効・無効 |
| `eyelid_output_cap` | `--eyelid-output-cap <value>` | 1、有限な 0..1 |
| `eye_widening_margin_left/right` | `--eye-widening-margin-left/right <value>` | 各0.10、有限非負 |
| `min_base_width` | `--min-base-width <value>` | 0.10、有限な0より大きく1以下 |
| `min_wide_width` | `--min-wide-width <value>` | 0.05、有限な0より大きく1以下 |

起動時の優先順位は明示 CLI > 保存設定 > 既定値。CLI 未指定と明示 false を区別する。起動後のパネルからの明示的な更新は、CLI由来の初期値も含めて現在値を上書きできる。保存値は次回起動に使うが、次回も同じCLIを指定すれば起動時はそのCLIが再び優先される。表示は現在適用中の値と更新元を示し、起動時の指定元と区別する。eye_wideningの既定値はtrueだが、測定済みの有効な区間がなければ EyeWide=0 のまま。
第一段階は手動測定とprofile保存・再利用を行う。profileには左右の測定値だけを保存し、数値設定は設定保存として独立させる。測定完了を理由にCLI由来の現在設定を保存しない。起動時にprofileを現在設定で再検証し、不正なら診断を出して未校正raw経路で起動する。有効な再キャリブレーションで不正な既存profileも上書きできる。再キャリブレーションの有効な結果で既存profileを上書きできることは必須。独立した削除/resetボタンは今回の対象外。装着状態が変わった場合はユーザーが手動で再測定する。自動学習を第一段階から除外し、後段のopt-inとする方針は選定済み。後段の学習方式・条件・設定の詳細は今回の対象外。自動装着検知は今回提案しない。
NaN/Infの設定値、逆転・等値・過小の基礎区間、不正なcap、非有限・負のmarginを拒否する。有限非負のmargin増加で見開き区間が不足する設定は受理し、その眼のEyeWide=0として基礎区間・測定wide値を保持する。起動時の不正CLI/設定はエラーとして扱い、稼働中の不正な更新は理由を通知して以前の有効設定・profileを保持する。
保存は途中書込みで有効profileを壊さない置換方式を用い、失敗を成功として表示しない。要求ID・保存境界・socketの契約は[IPC設計](2026-10-06-panel-ipc-design.md)に従う。
パネルからの操作も同じ `eye_widening` booleanをUnix pathname socket上のNDJSONで変更し、適用済み設定を表示する。保存writerはRust本体だけとし、独自のIPC経路を追加しない。
パネルで左右それぞれのデッドゾーン/見開き開始値を調整できるようにし、Rust 本体の適用済み値を表示する。幅 `d` と `wide_start` は測定値と左右別marginから算出する派生値とし、パネルの調整と整合させる。設定キーはIPC設計に定義し、具体的なUI形式は実装詳細とする。パネルでの明示的な調整と、区間成立のための暗黙の縮小を区別する。
追加余裕 `margin` は左右別に保存・指定できる既定値付きの設定とし、CLIとパネルの両方から変更できる。設定キーはIPC設計のeye_widening_margin_left/rightに対応し、左右とも既定0.10。起動時は他の設定と同じ明示CLI > 保存設定 > 既定値を使い、起動後はパネルの明示更新を現在値へ即時反映する。
最小基礎区間幅を増やして現在profile、またはactive測定の成功済みclosed/relaxed候補の基礎区間が不正になる更新はpatch全体を拒否し、旧設定・profile・成功候補を保持する。relaxed成功前は後のrelaxed段階を現在設定で検証する。最小見開き幅の変更は受理し、測定wide値を保持したまま利用可否を再判定する。派生値に影響するmargin・最小幅変更では対応フィルタをresetする。

## 既存フィルタとの順序

有効なprofileがある場合は、有限な raw → 左右別 Openness/EyeWide 正規化 → 各眼・各成分の独立 One Euro filter（既存の opt-in）→ 見開き合成 → 最終 clip → 既存 OSC 出力の順とする。profileがなければ前節のraw互換経路を使う。
One Euro の既存opt-inと調整値を基準とし、稼働中の有効・無効または3係数の変更時はフィルタ履歴をresetして反映する。フィルタ無効なら正規化値をそのまま合成する。clip をフィルタより後に置き、直前に cap を下げても送信値が上限を超えない。
追跡停止、時刻後退・重複、既存の大きなサンプル間隔での reset と、一時的な NoUpdate で履歴を保持する契約を尊重する。片眼raw欠落・非有限値・無効があればそのsnapshot全体を無効にし、現行のglobal inactiveとして両眼分の更新を止める方式とする。無効snapshotをフィルタへ渡さない。正常なraw=0は有効な閉眼であり、無効値として除外しない。
片眼だけの更新継続や短時間holdは今回の追加範囲に含めない。欠落を閉眼へ変換したり、他眼をコピーしたりしない。
profile・デッドゾーンの適用変更時はまぶたの正規化の意味が変わるため、その Openness/EyeWide の履歴を reset する。見開き有効化・cap の変更は合成後に即時反映する。
有効な見開き区間のフィルタは合成無効時も更新し、再有効化で古い見開き値を持ち込まない。見開き区間が無効な眼はフィルタ履歴からも見開きを生成せず EyeWide=0 とする。

## 検証と受入条件

- 正常区間と各境界の直前・一致・直後で有限・連続・単調。閉眼 0、自然開眼 0.75、十分な見開き 1 を cap=1・フィルタ無効で確認する。
- 左右で異なる raw 自然開眼が揃い、片眼だけの閉眼・見開きが他眼へ伝播しない。追加平均化がないことを非対称 fixture で確認する。
- 見開き無効で自然開眼と中間値が期待値を保持する。cap の 0、0.75 未満、0.75、1 と境界値を検証し、フィルタ有効時や cap 変更直後も上限を厳守する。
- 未測定見開き・飽和による片眼区間不足・不正 wide はその眼の EyeWide=0。wide=1.0で幅が成立する場合は有効。有効な基礎区間を失わず、反対眼から区間を借りない。
- NaN/Infの設定値、等値・逆転・過小の基礎区間、有効率不足を拒否し、失敗時に元の有効profileを保持する。測定中の無効値は欠測として数え、見開き区間不足はその眼のEyeWide=0とする。
- 保存・読込の往復、不正更新・保存失敗、CLI の明示 false と優先順位を検証する。見開き切替と profile 更新後のフィルタ履歴を確認し、既存追跡停止/NoUpdate の検証も保持する。
- profileなしのraw互換とcapのみの適用、各段階の準備2秒・計測5秒・中央値、有効サンプル率80%の境界、有効な再キャリブレーションによるprofile上書きを検証する。poll・重複timestampで率を水増しせず、producer更新頻度に応じた期待数を使うことを確認する。
- 自然開眼5秒の追跡有効な有限サンプルだけから左右別の最大値を取り、`wide_start=relaxed_max+margin` を検証する。測定済み自然開眼サンプルから見開きを生成せず、区間不足時は追加余裕を縮めずその眼のEyeWide=0とする。左右別のパネル調整と適用済み値の一致、設定可能な追加余裕・最小幅の変更と拒否境界を検証する。

実機で ABI v4 のヘッダ・サイズと、閉眼・自然開眼・見開き・左右ウィンク raw を各5秒採取した（[実機調査報告](../research/2026-10-03-steamframe-hardware.md)）。この装着下では左右とも自然開眼 p95 < 見開き p05 だった。校正・合成は実装済みで、自動検証と実機確認の範囲は[校正検証報告](../research/2026-10-10-calibration-verification.md)に記録する。装着変更、左右ウィンクの製品出力、デッドゾーン、最終出力・保存後の再利用の実機検証は残る。
ウィンク実測では両方向とも閉じた側 median < 反対側 median だったが、反対眼は自然開眼より低下した。反対眼の完全開眼維持は難しいとの操作者の申告があり、独立した開度基準の測定はない。この raw 低下をセンサ干渉や不具合とは断定しない。左右独立正規化・平均しない方針を維持し、反対眼の強制全開や完全開眼保持の受入条件を追加しない。
受入条件の自動テストは実機での快適さを代替しない。producer/ABI の意味、飽和特性、装着条件、アバターのパラメータ契約が変わった場合に、本機能の区間・提案閾値・合成の適用を再評価する。
